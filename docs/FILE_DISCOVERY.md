# איתור קובצי הוועדה ב-2026: איפה מחפשים, איך מאמתים, איך מחליפים

לחלק מהקבצים שהפיד צריך ביום הבחירות אין עדיין כתובת או פורמט ידועים לשנת 2026: שיעור ההצבעה לפי קלפי (החלטת היו״ר מ-16.8.2026), ובמידה פחותה גם קובצי התוצאות (`expb.csv`, `expc.csv`) והמעטפות הכפולות. מסמך זה מתאר את הכלי שמחפש אותם אוטומטית, איך קוראים את הדוח שלו, ומה עושים לכל קובץ בכל מצב.

סביבת הבנייה (וגם Claude, שמפעיל את האתר ביום הבחירות) אינה מגיעה ל-gov.il ול-bechirot.gov.il. שרתי GitHub כן מגיעים (נבדק ב-9.10.2026: `media22`–`media25` ענו, `media26` החזיר 404). לכן החיפוש רץ על שרתי GitHub, והדוח נשמר בענף נפרד שאפשר לקרוא מכל מקום.

## הכלי: `pipeline/discover.py` וה-workflow "Find the election files"

**מה הוא בודק.** בכל ריצה:

- הקבצים הידועים: `https://media26.bechirot.gov.il/files/expb.csv` ו-`expc.csv`, אותם שמות ב-`votes26` וב-`cdn-votes26`, והכתובות שרשומות כרגע ב-`pipeline/live_config.json`.
- קובץ ביקורת מ-2022: `https://media25.bechirot.gov.il/files/expc.csv`. אם גם הוא נכשל, השרת שהריץ את הבדיקה כנראה אינו מגיע לוועדה בכלל (ראו "כששרתי GitHub נחסמים").
- דפים שמהם נאספים קישורים: `votes26` (כולל `/nationalresults`, `/cityresults`, `/ballotresults`), `cdn-votes26`, `media26` (דף הבית, `/files/`, ורשימת קבצים בסגנון S3: `?list-type=2`, `?prefix=files/`), `bechirot.gov.il`, דפי שיעור ההצבעה ב-gov.il, `data.gov.il` ו-`robots.txt`/`sitemap.xml`. מכל דף נאספים קישורים, קובצי הסקריפט שהוא טוען (עד שתי רמות), כתובות שמופיעות בתוך הסקריפטים (`.csv`, `.json`, `.xlsx`, `/files/`, `/api/`), ודפי חדשות שהכתובת שלהם מדברת על הצבעה, קלפי או תוצאות (רמה אחת למטה). נבדקות רק כתובות בדומיין `gov.il`. מחרוזות חלקיות מתוך סקריפטים (למשל `"/files/turnout_"+h+".csv"`) מופיעות בדוח תחת `fragment` לקריאה ידנית.
- במצב `full` גם שמות מנוחשים: `exp[a-z].csv`, גרסאות json/xlsx/zip של `expb`/`expc`, כ-40 שמות אפשריים לקובץ השתתפות (`turnout`, `kalpi_turnout`, `voting_percentage`, `ahuz_hatzbaa` ועוד) כ-csv/json/xlsx, עם סיומות שעה (`turnout_14.csv`, `turnout_1400.csv`), ושמות לקובצי מעטפות. כ-390 כתובות, בקצב של לכל היותר 4 בקשות בשנייה לשרת.
- במצב `quick`: הקבצים הידועים, הדפים ומה שהם מקשרים אליו, וכל כתובת שענתה עם נתונים בדוח הקודם.

**מתי הוא רץ** (שעון ישראל): כל יום 15–26.10 ב-08:43 (מ-25.10 ב-07:43); ב-27.10 כל 20 דקות מ-06:07 עד 22:47 ועוד ריצה ב-23:07, כשהריצה של :07 בכל שעה מלאה (`full`) ושתי האחרות `quick`; ב-28–29.10 פעם בשעה ב-:13 (מלאה). אפשר להפעיל ידנית בכל עת: Actions → "Find the election files" → Run workflow, עם `mode` = `full` / `quick` / `auto`. בשדה `urls` אפשר לתת כתובות נוספות, מופרדות ברווח (למשל כתובת שהוועדה פרסמה בהודעה): הן נבדקות משרת GitHub כמו כל השאר, וגם הקישורים שבהן נאספים.

**לאן הדוח הולך.** לענף `ops-reports` בלבד: `reports/latest.md` ו-`reports/latest.json` (תמיד הדוח האחרון), ועותק לכל ריצה `reports/discover-YYYYMMDD-HHMM.{md,json}` (שעון ישראל). לא ל-`main`: כל דחיפה ל-`main` בונה את Pages מחדש, ויש מגבלה של כ-10 בניות בשעה. דחיפה ל-`ops-reports` אינה בונה את Pages. הסיכום הקצר מופיע גם בדף הריצה ב-Actions, והדוח המלא נשמר גם כ-artifact של הריצה (14 יום), כך שהוא זמין גם אם הדחיפה נכשלה.

- בדפדפן: `https://github.com/baselegbareia-beep/Elections/blob/ops-reports/reports/latest.md`
- משורת הפקודה: `git fetch origin ops-reports && git show origin/ops-reports:reports/latest.md`

**איך קוראים את הדוח.**

1. **שורת הביקורת** ("Control"): `200` = השרת מגיע לוועדה. `FAILED … this runner may not reach the CEC at all` = שום שרת של הוועדה לא ענה, וכל שאר התוצאות של הריצה חסרות משמעות לגבי הוועדה. `FAILED … other CEC hosts did answer` = רק `media25` נכשל.
2. **טבלת המפתחות**: לכל מפתח ב-`live_config.json` (`results_url`, `results_url_localities`, `station_turnout_url`) ולשיעור ההצבעה הארצי: הכתובת הנוכחית, המצב שלה, הצעה להחלפה ו-`column_aliases` נדרשים. המצבים:
   - `ok`: הכתובת עונה עם הסוג הנכון והקורא של הפיד מצליח לקרוא אותה.
   - `test file`: עונה, אבל זה קובץ בדיקה (אותיות של 2022, או שורות עם מצביעים לפני 22:00 ביום הבחירות). צפוי עד 27.10 22:00.
   - `reader fails`: עונה עם הסוג הנכון, אבל הקורא של הפיד נכשל (הסיבה בפירוט הקובץ).
   - `answers as error (404)` וכדומה: הכתובת הנוכחית אינה עונה עם נתונים.
   - `not set`: אין כתובת בהגדרות.
3. **"Suggested live_config.json change"**: הצעה בלבד. מאמתים לפי הסעיף הבא לפני שמעתיקים.
4. **שינויים מאז הדוח הקודם**: `new` (כתובת שהתחילה לענות או הופיעה לראשונה בדף), `changed` (קוד, סוג, גודל, SHA-256, `Last-Modified` או `ETag` השתנו) ו-`gone` (קובץ שענה ועכשיו לא, או קישור שנעלם). זה המקום הראשון לחפש בו קובץ חדש.
5. **סוגים** (`class`): `results-ballot` (תוצאות לפי קלפי), `results-locality` (לפי יישוב), `turnout-station` (מצביעים לפי קלפי), `turnout-locality` (השתתפות לפי יישוב), `turnout-national` (דף או קובץ עם שיעור הצבעה ארצי לפי שעות; המספרים שחולצו מופיעים בדוח, בהשתדלות), `listing` (רשימת קבצים של S3), `data-other` (קובץ נתונים שלא זוהה), `html`, `script`, `error`.
6. **טבלת השרתים**: כתובות IP (CloudFront או אחר), קודי תשובה ורמז: `S3: no such file` = השרת עונה והקובץ לא שם; `S3: access denied` = קובץ חסר כשאין הרשאת רשימה, או חסימה; `CloudFront: request could not be satisfied` או `blocked by a firewall rule` = חסימה; `Imperva bot protection` = הגנת בוטים של gov.il.

**הרצה ממחשב אחר** (מחשב נייד בישראל או runner עצמי): `python3 pipeline/discover.py --out disc` כותב `disc/report.md` ו-`disc/report.json`; עם `--push` הוא גם שומר את הדוח בענף `ops-reports` (צריך הרשאת push). numpy אינו חובה: בלעדיו הדוח לא מריץ את הקורא של הפיד על קובצי התוצאות ומציין זאת.

## איך מאמתים קובץ מועמד

לפני שמחליפים כתובת בהגדרות, כל התנאים האלה צריכים להתקיים בדוח:

1. **קוד 200 והסוג הנכון.** דף HTML (תחזוקה, דף שגיאה, או מעטפת של אתר שעונה 200 לכל כתובת: "same page as the site root") אינו קובץ נתונים.
2. **כותרת.** העמודות שהקורא מצפה להן קיימות, או ש-`column_aliases` בדוח ממפה אליהן. תוצאות: `סמל ישוב`, `שם ישוב`, `קלפי` (או `מספר קלפי`), `בזב`, `מצביעים`, `פסולים`, `כשרים`, ועמודה לכל רשימה. השתתפות לפי קלפי: `סמל ישוב`/`סמל יישוב`, `קלפי`/`מספר קלפי`, `מצביעים`/`הצביעו`, ו-`בזב`/`בעלי זכות בחירה` (בלעדיה אין אחוז הצבעה, רק קצב מול 2022).
3. **מספר שורות.** ב-2022: 12,545 שורות ב-`expb.csv`, מהן 11,707 קלפיות רגילות ו-838 שורות מעטפות (`סמל ישוב` 9999) בסוף; כ-1,215 יישובים. קובץ השתתפות לפי קלפי צריך להכיל סדר גודל דומה של קלפיות רגילות. `match_2022` (חלק הקלפיות שמספרן תואם ל-2022) צפוי להיות גבוה, ו-`arab_localities` קרוב ל-155/155. קובץ הבדיקה שצד שלישי ראה ב-5.10 הכיל 16 יישובים בלבד.
4. **אותיות.** `letters 2026` = לפחות 13 מ-15 האותיות של הרשימות שבסקרים (`מחל`, `דרך`, `רק`, `אמת`, `ל`, `שס`, `ג`, `ב`, `ט`, `ודם`, `עם`, `ך`, `די`, `כן`, `זך`; אותיות `ודם` טרם אומתו מול הוועדה). `2022 (a test file?)` = קובץ בדיקה.
5. **זמנים.** `Last-Modified` מהיום והשעה הנכונים; עמודת זמן אם יש (`data_time`); SHA-256 שמשתנה בין ריצות כשהוועדה מעדכנת. ביום הבחירות לפני 22:00, כל שורת תוצאות עם מצביעים היא נתון בדיקה.
6. **הקורא של הפיד.** `reader ok` בתוצאות פירושו שהקורא של הפיד (`read_expb`, במצב הסלחני של ליל הבחירות) קרא את הקובץ, עם ה-`column_aliases` וה-`ignore_columns` שבהצעה. בהשתתפות לפי קלפי הבדיקה היא של שמות העמודות בלבד.
7. **פורמט.** הפיד קורא CSV בלבד (UTF-8 עם BOM או windows-1255, שניהם בסדר). JSON או xlsx מסומנים `reader FAILS` עם הסבר: נדרש ממיר, כלומר שינוי קוד.

## איך מעבירים את הפיד לכתובת חדשה

עורכים את `pipeline/live_config.json` בענף `main` (סמל העיפרון ב-GitHub, או commit). הפיד קורא את הקובץ מחדש בכל סבב, כך שהשינוי נכנס לתוקף תוך דקה–שתיים. כל commit ל-`main` הוא בניית Pages, ולכן מרכזים את כל השינויים ב-commit אחד.

| מפתח | מתי משנים | דוגמה |
|---|---|---|
| `results_url` | קובץ התוצאות לפי קלפי עבר כתובת | `"https://media26.bechirot.gov.il/files/expb.csv"` |
| `station_turnout_url` | נמצא קובץ ההשתתפות לפי קלפי (או כתובת של פרסום חדש, אם לכל פרסום שם משלו) | `"https://…/files/<השם שבדוח>.csv"` |
| `column_aliases` | כותרת שהשתנתה: `{"השם אצלם": "השם הצפוי"}` | `{"מס' קלפי": "קלפי", "קוד ישוב": "סמל ישוב"}` |
| `ignore_columns` | עמודה מספרית שאינה רשימה ושוברת את סכום הקולות | `["סהכ"]` |
| `results_url_localities` | לתיעוד בלבד: הפיד אינו קורא את `expc.csv` | |

- `column_aliases` חל היום על קובץ התוצאות. אם בדוח מופיע "live_fetch.station_turnout does not apply column_aliases yet", קורא ההשתתפות לפי קלפי אינו משתמש בו, ומיפוי כותרות שם הוא שינוי קוד קטן (או תמיכה ב-`column_aliases` גם שם).
- החלפת `results_url` מאפסת את מצב הפיד (המצב של מקור אחר אינו בשימוש), והספירה נבנית מחדש מהקובץ החדש.
- אחרי ההחלפה בודקים בסבב הבא את `status.json` של הפיד (`results_state`, `errors`) ואת `turnout.json` (`sectors` קיים, אין `station_error`). איפה הקבצים האלה מתפרסמים: `docs/ELECTION_DAY.md`.
- אם המצב לא ברור: `"projection_paused": true` עם `pause_reason` מסתיר את התחזית ומשאיר את הספירה.

## עץ החלטות לכל קובץ

### 1. תוצאות לפי קלפי (`expb.csv`)

איפה קודם: `https://media26.bechirot.gov.il/files/expb.csv` (הנתיב של 2019–2022). בדוח: השורה `results_url`.

1. עד 27.10 22:00: `test file` או 404 עם `S3: no such file` הם צפויים. לא נוגעים.
2. מ-22:00: הפיד מושך בעצמו. אם `results_state` הוא `waiting` לאורך זמן, ייתכן שהקובץ פשוט עוד ריק (2021: השורות הראשונות ב-01:01). מחפשים בדוח של :07/:27/:47:
   - הכתובת הנוכחית `ok` עם אותיות 2026 ושורות שמתווספות: הכול תקין.
   - הכתובת הנוכחית נכשלת והביקורת (media25) עונה: לפי הרמז. `S3: no such file` = הקובץ לא הועלה, ממתינים ובודקים אם הופיע קובץ `results-ballot` בכתובת אחרת (`new`). אם יש מועמד שעבר את האימות: מחליפים `results_url`.
   - גם הביקורת נכשלת, או רמז של חסימה: שרתי GitHub חסומים (ראו למטה).
   - הקובץ עונה אבל `reader FAILS`: מעתיקים את `column_aliases` / `ignore_columns` מההצעה, אחרי שבודקים שהמיפוי הגיוני.
3. אם הוועדה מפרסמת רק JSON (כתובת `/api/…` מתוך הסקריפטים של `votes26`) או רק טבלאות HTML (`/ballotresults`): אין מסלול מוכן. צריך ממיר שמייצר קובץ בפורמט `expb.csv` (שינוי קוד; הדוח מראה את הכותרת והשורות הראשונות). עד אז: `projection_paused` עם `pause_reason` שמפנה לאתר הוועדה.
4. מוצא אחרון: מראה של צד שלישי (ראו למטה).

### 2. תוצאות לפי יישוב (`expc.csv`)

איפה קודם: `https://media26.bechirot.gov.il/files/expc.csv`. הפיד אינו משתמש בקובץ הזה; הוא נבדק כסימן לכך שהשרת עלה ושהפורמט לא השתנה (שני הקבצים התעדכנו יחד ב-2019–2022). אם קיים רק `expc.csv` ולא `expb.csv`, הפיד לא יכול לחשב תחזית לפי קלפי; זה שינוי קוד.

### 3. שיעור ההצבעה לפי קלפי (פרסום היו״ר)

מה ידוע: לפחות ארבעה פרסומים ביום הבחירות (ערוץ 12: "כל ארבע שעות"), מצרפי לכל קלפי רגילה. שעות, כתובת ופורמט לא פורסמו (נכון ל-9.10). ההודעות צפויות מהמנכ״ל בפועל, דין ליבנה, או מאתר הוועדה.

איפה קודם: בדוח, השורה `station_turnout_url` וכל שורת `turnout-station` ב-`new`. החיפוש האוטומטי מכסה שמות מנוחשים תחת `/files/` (עם סיומות שעה), קישורים ב-`votes26`/`cdn-votes26`, כתובות בתוך הסקריפטים שלהם, דפי חדשות ב-`bechirot.gov.il`, ורשימת הקבצים של `media26` אם היא פתוחה.

1. הופיע קובץ `turnout-station`: מאמתים (מספר קלפיות, `match_2022`, `arab_localities`, אחוז הצבעה סביר מול הנתון הארצי של אותה שעה, `Last-Modified` מ-27.10 אחרי שעת הפרסום).
   - CSV ו-`reader ok`: `station_turnout_url` = הכתובת.
   - CSV עם כותרות אחרות: `column_aliases` אם הקורא תומך בו (ראו ההערה למעלה), אחרת שינוי קוד.
   - עמודת מצביעים לפי שעות (`מצביעים עד 14:00`…): הדוח ממפה את העמודה האחרונה; לוודא שזו השעה העדכנית.
   - רק אחוז הצבעה בלי מספר מצביעים, או JSON / xlsx: שינוי קוד (חישוב מצביעים = אחוז × בעלי זכות, או ממיר).
2. לכל פרסום כתובת משלו (שם עם שעה): מעדכנים את `station_turnout_url` אחרי כל פרסום (ארבעה commits ביום).
